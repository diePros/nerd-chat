A message has no place to rest

There is no server in the middle. Each contact gets its own key pair and its own Tor onion service, and your messages live in memory unless you choose otherwise.

  1. You connect to one onion service created only for that contact, protected by v3 client authorization.
  2. The two sides run a Noise handshake with fresh ephemeral keys, so each connection has its own keys.
  3. Every message travels as a signed, encrypted 1 KiB cell with no timestamp on the wire.

Where it runs

Linux terminal
One static x86_64 binary. Runs from a live USB. Needs tor installed, or an existing Tor via --tor-control.
Linux desktop
A native Rust app, packaged as a .deb. Targeted for 0.2.
Android
Kotlin and Compose over the same Rust core, with Tor embedded. It reaches “Tor connected” on an emulator. It has not run on a real phone yet.
Not planned
macOS, Windows, groups, voice and video, any cloud or account.

      Status and limits

      • Unaudited. Version 0.1.0. It has had no independent professional audit.
      • 33 review rounds, by AI. Adversarial reviews by Claude Opus are tracked finding by finding. They are not a substitute for a human audit.
      • Online only. Both people must be online unless the optional encrypted outbox is on.
      • Your online time is visible to anyone who knows a contact's onion address. Treat a shared bundle as confidential and rotate keys when in doubt.
      • Out of reach for any software like this: a compromised device, a global observer correlating traffic, and RAM remanence.
      • Android on a real phone has not been tried. The Android storage and key-erasure code has never run on a device.

      Not a replacement for a tool you can trust with your life. Report vulnerabilities through GitHub's private “Report a vulnerability” form on the repository.
